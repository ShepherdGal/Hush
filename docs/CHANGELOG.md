## Cleaning cue: Smash — November 12, 2026 (unreleased)

- **`UI/ScanActivity.cs` is now "Smash"** (owner's pick from four concepts, then two refinements; "B, soft plate"; no spark on the ring tip). Dust drifts in from the rim and spirals into a core that charges, squashes and smashes: white flash, a fast shockwave ring with a thinner one behind it, 18 sparks. The blast wipes every speck still on its way, the field is calm, and a new cycle starts. A cycle is 3.78 s (3.6 s slowed by 5%).
- **It loops until the clean really finishes, then ends on purpose.** `ScanActivity.FinishAsync()` (called with `CompleteGauge(mission: true)` after a finished clean, real app window only) fast-forwards the dust and lands ONE bigger, slower final smash (1.5 s, a third ring). A stopped or failed clean just stops the cue.
- **The percentage stays readable:** a soft plate (eight translucent discs in the panel color, built once) fades whatever passes under the digits.
- **Extras kept:** the percentage swells a little at each smash and the gauge ring's glow flares (`UI/MainWindow.CleaningCue.cs`, the `Smashed` event; one short self-releasing animation each). The spark on the ring tip was dropped on request.
- **Built to the rulebook:** all shapes built once and lazily; transform/opacity only; glows are stacked translucent discs; a cycle is two short storyboards chained by their Completed events (no timer, no `RepeatBehavior.Forever`, no mask, clip or effect, no frame-rate cap). Stopping releases every animated property directly (a hand-over between storyboards can otherwise leave a snapshot behind).
- Tests: `UiLayoutChecks.VerifyCleaningCue` (plays, rests, smashes by itself, finale ends with exactly one final smash and then rests); `--preview-cleaning` now renders a series through the cycle. Verify passes; previews looked at in Dark and Light. **Not verified:** the live feel and frame rate (run `scripts/Perf.ps1` and watch it), a real weak PC, the one-frame label clip seen once in a preview capture (not reproduced).

## Minimal clean result, honest Windows Update reports — November 11, 2026 (unreleased)

- **Clean result is now one short line.** After a clean the Home status reads "Cleanup complete · 5.1 MB freed" (or "Stopped safely · ... freed"); a second line appears only when files were left alone ("4 files were left alone"). The rest (how many were cleaned, how many skipped and why, what the disk itself reports, how much is still found) is on hover over the result line. The result still stays on screen (the 0.9 rule). Test updated.
- **"Turn off Windows Update" — the real cause (owner: "the button is faded and cannot even be pressed").** The confirmation's consent box ("I understand my PC gets no security fixes...") uses the Review checkbox style, whose enabled state follows "a scan result can be selected". With no scan result on screen (the normal case when you open Settings) the box was disabled, so it could not be ticked and the "Turn off Windows Update" button, which stays disabled until the box is ticked, could never be pressed. The same style made "Also turn off Windows Update" (Apply all settings) and the System Protection box dead too. They are now always enabled (a local value in MainWindow.xaml); the earlier test ticked the box from code, which skipped this. New checks assert the boxes are enabled while no scan result exists (`CanSelectCandidates` is false) in both flows; the render shows the box bright instead of dimmed.
- **Also checked and fixed in the Windows Update module.** Checked on this PC (read-only): the four update services are all Manual again, no history file exists, and on this Windows build (11, 26200) administrators ARE allowed to change all four services including WaaSMedicSvc (service rights and registry ACL), so the old assumption that WaaSMedicSvc is always protected does not hold here. Found and fixed by reading the code: (1) **Turning back on could never finish** if Windows had refused to disable a task: the restore tried to enable a task that was still enabled, failed, and kept Hush "off" with the red line forever; tasks that still have their old state are now skipped. (2) **A run in which Windows refused everything still left the red "Windows Update is off" line**; now nothing is saved as "off" unless something really changed. (3) **Refusals gave no reason**; the report now carries the tool's own words ("[SC] ChangeServiceConfig FAILED 5: Access is denied.", "ERROR: Access is denied.") and each run is also written to `Windows settings\windows-update-last-run.txt`. (4) The result popup is worded by what happened: "was not turned off", "partly turned off" or "turned off".
- Tests: new `WindowsUpdateChecks.RunReports` (refused-everything, refused-only-tasks, back on, one-line reasons) with fakes only; the UI test now expects "partly turned off" for the fake whose WaaSMedicSvc refuses. Verify passes (463 checks + UI); exe rebuilt. **Not verified:** the real switch (never run on this PC), so whether it now works end to end on the owner's PC is still open; the new report file will show exactly what Windows refuses.

## Scheduled tasks card — November 9, 2026 (unreleased)

- **New: Settings > Scheduled tasks** (owner: "also clean unneeded tasks"), the sibling of Services. It lists scheduled tasks most home PCs do not need from a curated catalog of 33 entries (telemetry and diagnostics, phone/maps/family/games, app updaters) plus tasks left behind by removed programs, under four collapsible topics that always start closed. Switch ON = enabled as Windows has it now; OFF stages "turn it off". Review shows exactly what changes; without administrator rights it offers *Restart as administrator* (`--tasks`, `--tasks-undo`). The change is Disabled via `schtasks.exe` (nothing is deleted), the original state is saved to `Windows settings\tasks-changed.json` first, every change is read back and logged (`Logs\tasks.jsonl`), and Undo turns them back on. Never touched: anything under `\Microsoft\Windows\` outside the exact catalog, the Windows Update / Defender / restore / servicing / time / BitLocker / defrag / security folders, any path with Antivirus/Defender/Firewall/Security, Hush's own task. The history is allow-listed on load (forged entries reported, never acted on). The list is read when the card is opened, never when Settings opens.
