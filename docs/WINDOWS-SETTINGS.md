# Windows settings

How the Settings page's Windows choices work (0.8.2). Read with CLAUDE.md. This documents the catalog (about eighty choices, grouped by topic) and its safeguards; the catalog can be expanded (more policies, services, scheduled tasks, app removal, etc.) when the user asks. New tweaks should keep the confirmation + Undo pattern where Windows allows it. No actual Windows policy was applied during verification.

## Supported choices

The catalog in WindowsSettings.cs is a list of known entries; UI and history contain catalog IDs, never executable commands or caller-supplied registry destinations. All entries use REG_DWORD. Per-user entries use HKCU; device-wide entries (marked Machine in the catalog, administrator required) use the 64-bit HKLM view. No service/task/package/security changes are included.

| Choice | Scope and exact value | Effect and limits |
| --- | --- | --- |
| Limit optional diagnostic data | HKCU `Software\Policies\Microsoft\Windows\DataCollection`, `AllowTelemetry=1` | Requests required-only Windows diagnostics for this user. Required data remains; other apps have independent controls. Existing stricter values are never weakened. |
| Stop personalized offers from diagnostic data | HKCU `Software\Policies\Microsoft\Windows\CloudContent`, `DisableTailoredExperiencesWithDiagnosticData=1` | Prevents diagnostic-data personalization of Windows content; suggestions can remain. This does not itself reduce collection. |
| Hide suggestions in Windows Settings | HKCU `Software\Policies\Microsoft\Windows\CloudContent`, `DisableWindowsSpotlightOnSettings=1` | Removes suggested Settings content on Enterprise/Education/IoT Enterprise; disabled on Pro. |
| Turn off location for this user | HKCU `Software\Policies\Microsoft\Windows\LocationAndSensors`, `DisableLocation=1` | Stops Windows location access for this user. Maps/location-dependent features can be affected. IP-based website estimates remain possible. Separate impact disclosure. |
| Turn off Windows Widgets | HKLM `SOFTWARE\Policies\Microsoft\Dsh`, `AllowNewsAndInterests=0` | Disallows Widgets across users, including taskbar content. No uninstall. Requires an already elevated app. Separate impact disclosure. |
| Stop Office from sending diagnostic data | HKCU `Software\Policies\Microsoft\office\common\clienttelemetry`, `sendtelemetry=3` | Office diagnostic data level "Neither". Office keeps working. |
| Stop Office from sending personal information | HKCU `Software\Policies\Microsoft\office\16.0\common`, `sendcustomerdata=0` | Office's "Send personal information" policy off. |
| Opt out of the Office Customer Experience Improvement Program | HKCU `Software\Policies\Microsoft\office\16.0\common`, `qmenable=0` | Office stops reporting feature usage. (Office 2016, 2019, 2021 and Microsoft 365 all use the `16.0` key.) |
| Keep web suggestions out of Start search | HKCU `Software\Policies\Microsoft\Windows\Explorer`, `DisableSearchBoxSuggestions=1` | Start search stays local. |
| Stop collecting typing and inking samples | HKCU `Software\Policies\Microsoft\InputPersonalization`, `RestrictImplicitTextCollection=1` | No personal dictionary learned from typing. |
| Limit Windows telemetry to required data | HKLM `SOFTWARE\Policies\Microsoft\Windows\DataCollection`, `AllowTelemetry=1` | Required level for every user (the Connected User Experiences and Telemetry service stays installed; Windows has no full off switch on Pro). |
| Stop Windows feedback prompts | HKLM `...\DataCollection`, `DoNotShowFeedbackNotifications=1` | No feedback pop-ups. |
| Turn off the advertising ID | HKLM `SOFTWARE\Policies\Microsoft\Windows\AdvertisingInfo`, `DisabledByGroupPolicy=1` | Apps cannot use an advertising ID. |
| Opt out of the Windows Customer Experience Improvement Program | HKLM `SOFTWARE\Policies\Microsoft\SQMClient\Windows`, `CEIPEnable=0` | Windows CEIP off. |
| Stop the application inventory collector | HKLM `SOFTWARE\Policies\Microsoft\Windows\AppCompat`, `DisableInventory=1` | No installed-program inventory for compatibility telemetry. |
| Turn off activity history | HKLM `SOFTWARE\Policies\Microsoft\Windows\System`, `EnableActivityFeed=0` | No timeline recording or sync. |
| Stop sharing Windows updates with other PCs | HKLM `SOFTWARE\Policies\Microsoft\Windows\DeliveryOptimization`, `DODownloadMode=0` | HTTP-only downloads from Microsoft; no peer-to-peer upload (saves upload bandwidth). |
| Stop automatic offline-maps downloads | HKLM `SOFTWARE\Policies\Microsoft\Windows\Maps`, `AutoDownloadAndUpdateMapData=0` | No background map downloads or updates. |
| Turn off Windows Error Reporting (Advanced) | HKLM `SOFTWARE\Policies\Microsoft\Windows\Windows Error Reporting`, `Disabled=1` | No crash reports sent to Microsoft. Separate impact disclosure. |
| Stop Store apps running in the background (Advanced) | HKLM `SOFTWARE\Policies\Microsoft\Windows\AppPrivacy`, `LetAppsRunInBackground=2` | Store apps stop background refresh (saves bandwidth); mail, calendar and chat apps may stop notifying until opened. Desktop programs unaffected. Separate impact disclosure. |

Microsoft documents diagnostic policy in both user/device scope and uses the stricter configured setting. See [System/AllowTelemetry](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-system#allowtelemetry) and [diagnostic configuration guidance](https://learn.microsoft.com/en-us/windows/privacy/configure-windows-diagnostic-data-in-your-organization). Personalization and Settings-suggestion scope/edition mappings come from [Experience policies](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-experience). Location uses the user [Sensors policy](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-admx-sensors#disablelocation-1); Widgets uses the stable [AllowNewsAndInterests policy](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-newsandinterests#allownewsandinterests), not the newer Insider-only alternatives. Local Windows 25H2 ADMX definitions were also inspected to verify DWORD mappings. The Office values (`sendtelemetry`, `sendcustomerdata`, `qmenable`) come from the Office ADMX templates as mirrored by DISA STIG and CIS Office benchmarks; the advertising ID (`DisabledByGroupPolicy`) and Windows CEIP (`CEIPEnable`) values from Microsoft's policy CSP and Win32 documentation. Tests only write to fixture roots, so none of these values has been applied to a real Windows installation.

## Availability and policy ownership (November 8, 2026: no more read-only locks)

Earlier versions locked every switch as "read-only" on Windows Home, on builds above 25H2 and on any PC they believed was managed. The managed test was wrong on nearly every PC (Windows 11 always has built-in "Local/Cloud/Deploy Authority" enrollment entries, and `NetGetAadJoinInformation` answers 1, "not joined", on an ordinary PC), so Hush was read-only almost everywhere. Now:

- **Managed** means domain-joined (`NetGetJoinInformation` status 3), Entra ID-joined (`NetGetAadJoinInformation` returns 0 with join info), or enrolled with a real device-management service (enrollment state 1 with a provider that is not one of the built-in authorities, or with a UPN). A managed PC gets a warning on the Settings card (its own rules may override or undo the choices); nothing is locked.
- **Windows Home / newer builds / Enterprise-only choices:** never locked. The card says Home ignores several of these policies; the suggestions choice carries the note "Only takes effect on Enterprise or Education".
- **Values already set outside Hush** (by Windows, another tool or a policy) are shown with a note and can be changed after the confirmation. The first value Hush ever saw is saved as the original (`SavedValue.Original`, any DWORD or absence), what Hush wrote is saved as `Applied`, and Undo restores the original exactly. Tracking ends when a setting is back at its original. Undo still refuses to overwrite a value that someone changed after Hush set it. History files without `Applied` (older versions) still load; their applied value is the setting's "on" value.
- **A device policy that overrides a per-user choice** is explained in the row, not locked.
- **What still blocks a switch** (`CanEdit = false`): an interrupted operation that must be undone first, and a value of an unusual registry type (not DWORD) that Hush could not put back exactly.

## Administrator rights, confirmation and restart advice

Device-wide choices (the `Machine` ones) need administrator rights. They stay usable: when the plan contains one and Hush is not elevated, the confirmation says so and its button reads "Restart as administrator". Nothing is written at that point. Hush starts a copy of itself with the Windows permission prompt (`runas`) and `--windows-review +id,-id` (or `--windows-undo`), then exits; the elevated copy opens Settings, stages only ids that exist in the catalog and shows the normal confirmation again, so the person always confirms once more. Declining the prompt changes nothing and keeps the choices staged. `Execute` itself refuses a device-wide change when not elevated. Tests replace `MainWindow.ElevatedLauncher` and `ExitForRestart`; never start a real prompt to test.

Every confirmation ends with a plain instruction: restart the PC after device-wide changes, sign out and back in (or restart) after per-user ones. After a successful change the same popup stays open as a result ("Windows changes applied" with that advice and a Close button). Hush never restarts or signs out Windows itself, restarts Explorer, disables security or deletes packages. The UI says policy values were saved and verified; it cannot prove that Windows components have refreshed.

## Confirmation, durability and recovery

Checkboxes stage desired values only. Review captures an immutable expected/target plan. The dedicated modal lists the changes and effects; only its Apply/Undo action runs the backend. Cancel/Escape does not write. A confirmed uncheck restores only that tracked choice's original state; Undo changes restores all tracked choices. There is no blanket Restore Defaults that could overwrite another configuration.

Before mutation, the backend locks its local history and rechecks every expected value, account, support condition and permission requirement. It checks again before each write. Account-bound pending originals are flushed to `%LOCALAPPDATA%/Hush/Windows settings/windows-settings.json` before the first mutation. Writes are flushed/read back; history commits through a fresh temporary file and same-directory atomic rename. No arbitrary paths or restoration values are accepted from history; invalid schema, owner, IDs, duplicate entries, oversized data, non-absent originals and linked history paths are rejected. The file lock serializes Hush instances using that history directory.

On failure, rollback restores only attempted values that still match Hush's target, retaining pending history even if rollback succeeds. A new instance can review Undo to reconcile target/original values and clear the recovery state. A different current value, newly detected management/device policy or missing administrator access blocks restoration rather than overwriting it. Read/Refresh never performs automatic recovery. Corrupt/foreign history is retained and disables changes; do not delete it automatically to unblock writing.

Registry operations use optimistic expected-value checks, not an OS-wide atomic transaction. Another tool can race or later replace the same policy. Readback confirms stored registry data at that moment, not effective Windows behavior. Preserve this distinction in future UI/tests/release claims.

## Verification rule

`--verify-windows-settings` is mandatory in scripts/Verify.ps1. Native production probes are read-only. Every test write, including simulated machine policies, is mapped to one freshly generated `HKCU\Software\Hush.TestFixtures\GUID` root; it never invokes production registry Write. The test checks the root prefix/GUID before removing it. File history lives only inside the unique UI fixture. No real policy change, installed-app self-update or user cleanup is part of verification.

## Levels and the 0.8.2 catalog

Modeled on O&O ShutUp10++, which rates every choice Recommended, Limited recommended or Not recommended. Hush offers only two levels: **Recommended** (Privacy & telemetry card: little or no effect on how Windows works) and **Somewhat recommended** (More impact card, `WindowsAdjustment.Advanced`: useful for privacy, but some apps or features can stop working). Choices ShutUp10++ would rate "not recommended" are never offered, and a test fails if the catalog gains a camera, microphone, location-access, Defender, SmartScreen, Windows Update, Store, OneDrive, sign-in or security choice. O&O does not publish its per-setting ratings, so the ratings here are Hush's own, following that scheme; every choice is a documented Windows or Edge policy value under a `Policies\Microsoft` key (REG_DWORD), device-wide unless the description says "for this user".

Topics (the group headings): Telemetry & diagnostics, Suggestions & ads, Search & Cortana, Apps & permissions (value 2 = denied), Activity history & sync, Typing & handwriting, AI features (Recall, Copilot), Microsoft Edge, Microsoft Office, Location & maps, Apps & background, Windows Update & maintenance. Choices that only take effect on Enterprise/Education (consumer features, cloud-optimized content, tips, Spotlight, third-party suggestions) carry the note "Only takes effect on Enterprise or Education". Edge shows "managed by your organization" once any Edge policy is set; the Edge heading says so.

## Settings layout and the Actions menu (0.8.3)

One line per choice (switch, name, "?", level dot), the explanation in the "?" popup, collapsible topic groups, a search box and an **Actions** menu in the footer. Actions only stage switches and open the normal confirmation (nothing is written before it): *Apply only recommended settings* (green: Recommended choices that take effect on this PC), *Recommended and somewhat recommended settings* (amber: plus the Somewhat recommended ones), *Apply all settings* (red: every available choice, including those that only take effect on Enterprise/Education). The amber and red actions differ only by those Enterprise-only choices because choices ShutUp10++ would call "not recommended" are never offered.
